DIFFERENCE REWARD IMPLEMENTATION - CHANGE REPORT
============================================================================================
Date: 2025-08-09
Implementation: Difference-reward scheme with per-step normalization

============================================================================================
SUMMARY OF CHANGES
============================================================================================

This report documents the implementation of a difference-reward scheme to replace the original
incremental latency-based rewards. The new system uses a non-mutating preview mechanism to
evaluate both local and remote options before committing to an action, then provides normalized
feedback based on the quality of the decision.

============================================================================================
FILE-BY-FILE CHANGES
============================================================================================

1. env/mec_offloaing_envs/offloading_env.py
-------------------------------------------

MODIFICATIONS:

a) Class Constructor (__init__):
   - Added new parameters:
     * use_difference_reward=True: Toggle between old and new reward schemes
     * reward_clip_range=(-2.0, 2.0): Final reward clipping bounds  
     * epsilon=1e-9: Numerical tolerance for equality checks
   - Added diagnostic_data dictionary to track:
     * delta_loc, delta_rem: Incremental makespan for each option
     * delta_chosen, delta_best, delta_worst: Decision metrics
     * r_main, r_norm: Raw and normalized rewards
     * action_is_best: Whether the chosen action was optimal

b) New Method: dry_run_preview()
   - Purpose: Non-mutating preview of scheduling decisions
   - Inputs: task_id, action (0/1), task_graph, current_state
   - Output: delta_makespan for the given action
   - Implementation:
     * Calculates timing for local or remote execution
     * Does NOT modify any state variables
     * Returns incremental makespan (candidate_makespan - current_makespan)

c) New Method: get_scheduling_cost_with_difference_reward()
   - Purpose: Main reward calculation with difference scheme
   - Process for each task:
     1. Preview both options (local and remote) using dry_run_preview
     2. Calculate deltas: delta_loc, delta_rem
     3. Compute r_main = delta_best - delta_chosen
     4. Normalize: r_norm = r_main / (delta_worst - delta_best) if different
     5. Clip to [-1, 1] then to reward_clip_range
     6. Execute chosen action and update state
   - Tracks all diagnostic data for analysis

d) Modified Method: get_reward_batch_step_by_step()
   - Added conditional logic based on use_difference_reward flag
   - If True: Uses get_scheduling_cost_with_difference_reward()
   - If False: Uses original get_scheduling_cost_step_by_step()

e) New Method: get_diagnostic_summary()
   - Computes summary statistics from diagnostic data
   - Returns averages and fractions for logging
   - Metrics include:
     * Average deltas for each option
     * Average rewards (raw and normalized)
     * Fraction of best actions taken
     * Fraction of positive rewards

LEVEL 2: CRITICAL-PATH POTENTIAL SHAPING IMPLEMENTATION - CHANGE REPORT
============================================================================================
Date: 2025-08-12
Implementation: Critical-path potential shaping added to difference-reward scheme
============================================================================================

============================================================================================
SUMMARY OF CHANGES
============================================================================================

This report documents the implementation of critical-path potential shaping to enhance
the existing difference-reward scheme. The shaping term provides additional guidance
based on the reduction in remaining critical-path time, helping the agent learn more
efficiently by considering long-term implications of scheduling decisions.

============================================================================================
KEY FEATURES IMPLEMENTED
============================================================================================

1. **Non-mutating Critical Path Computation**: Calculates remaining critical-path time
   for unscheduled tasks without modifying live scheduling state

2. **Potential-Based Shaping**: Adds shaping term based on CP reduction between states

3. **Runtime Configuration**: All parameters configurable at runtime without code changes

4. **Comprehensive Diagnostics**: Tracks CP metrics for monitoring and analysis

5. **Invariant Assertions**: Validates CP behavior during training

============================================================================================
FILE-BY-FILE CHANGES
============================================================================================

1. env/mec_offloaing_envs/offloading_env.py
-------------------------------------------

MODIFICATIONS:

a) Class Constructor (__init__):
   Added new parameters for critical-path shaping:
   - cp_shaping_enabled (bool): Default True, enables the feature
   - cp_discount (float): Default 0.99, discount factor for CP shaping
   - cp_coefficient (float): Default 1.0, scaling factor for shaping contribution
   - cp_normalize_mode (string): Default "none", options: "none", "divide_by_p75"
   - cp_scale (float): Default None, scale value for normalization
   - small_threshold (float): Default 1e-9, tolerance for numeric comparisons

b) New Method: compute_remaining_critical_path()
   - Purpose: Calculate critical-path time for remaining unscheduled tasks
   - Implementation:
     * Identifies remaining tasks (all tasks - scheduled tasks)
     * Computes best single-node duration for each remaining task:
       node_duration = min(local_exec_time, uplink + edge_exec + downlink)
     * Builds topological ordering of remaining sub-DAG
     * Computes longest path using dynamic programming:
       accumulated[u] = node_duration[u] + max(accumulated[predecessors])
     * Returns maximum accumulated value (critical path)
   - Complexity: O(V + E) where V = remaining tasks, E = edges in sub-DAG

c) Modified Method: get_scheduling_cost_with_difference_reward()
   Enhanced with CP shaping integration:
   - Tracks scheduled_tasks set throughout episode
   - For each scheduling decision:
     1. Computes base difference reward as before
     2. If cp_shaping_enabled:
        * Calculates cp_before on current remaining tasks
        * Calculates cp_after with task added to scheduled set
        * Applies normalization if configured
        * Computes shaping_contribution = cp_coefficient * (cp_before - cp_discount * cp_after)
     3. Combines: final_step_score = r_norm + shaping_contribution
     4. Clips final score to reward_clip_range
   - Assertions:
     * cp_after <= cp_before + small_threshold (CP must not increase)
     * At episode end: remaining CP <= small_threshold

d) Enhanced Diagnostic Tracking:
   Added new diagnostic fields:
   - cp_before: CP value before each action
   - cp_after: CP value after each action
   - cp_reduction: (cp_before - cp_after) for each step
   - shaping_contribution: Shaping term value
   - shaping_ratio: |shaping_contribution| / (|base_reward| + ε)
   - final_step_score: Combined reward after shaping

e) Updated Method: get_diagnostic_summary()
   Added CP-related summary statistics:
   - avg_cp_before, avg_cp_after, avg_cp_reduction
   - avg_shaping_contribution, avg_shaping_ratio
   - avg_final_step_score, max_shaping_ratio
   - fraction_positive_final: Fraction of positive final rewards

============================================================================================
MATHEMATICAL FORMULATION
============================================================================================

1. Node Duration Calculation:
   For each remaining task u:
   node_duration(u) = min(
       local_exec_time(u),
       uplink_time(u) + edge_exec_time(u) + downlink_time(u)
   )

2. Critical Path Computation:
   For remaining task DAG in topological order:
   accumulated[u] = node_duration(u) + max({accumulated[p] : p ∈ predecessors(u)})
   CP = max({accumulated[u] : u ∈ remaining_tasks})

3. Shaping Term:
   shaping_contribution = cp_coefficient × (cp_before - cp_discount × cp_after)
   
   With optional normalization:
   If cp_normalize_mode == "divide_by_p75" and cp_scale > 0:
       cp_normalized = cp / cp_scale
   
4. Final Step Score:
   final_score = base_difference_reward + shaping_contribution
   final_score = clip(final_score, reward_clip_range)

============================================================================================
DESIGN RATIONALE
============================================================================================

1. **Non-Mutating Computation**: CP calculation doesn't modify scheduling state,
   ensuring consistency and enabling safe preview of future states

2. **Potential-Based Shaping**: Following Ng et al. (1999), using potential difference
   ensures policy invariance - optimal policy remains optimal with shaping

3. **Discount Factor**: cp_discount < 1 prevents infinite reward loops and ensures
   convergence, while still providing lookahead guidance

4. **Normalization Options**: "divide_by_p75" mode allows adaptation to different
   problem scales without manual tuning

5. **Diagnostic Tracking**: Comprehensive metrics enable monitoring of shaping
   influence and detecting potential issues like shaping domination

============================================================================================
INVARIANTS AND GUARANTEES
============================================================================================

1. **Monotonicity**: CP never increases after scheduling a task
   - Enforced by assertion: cp_after <= cp_before + small_threshold

2. **Termination**: At episode end, all tasks scheduled → CP = 0
   - Enforced by assertion: final_cp <= small_threshold

3. **Bounded Influence**: Shaping contribution bounded by design
   - cp_coefficient controls maximum influence
   - reward_clip_range provides final bounds

4. **Policy Preservation**: Potential-based design preserves optimal policy
   - Shaping only changes value function, not optimal actions

============================================================================================
EXPECTED BEHAVIOR
============================================================================================

1. **Early Training**: High shaping_ratio as agent learns basic scheduling

2. **Mid Training**: Decreasing shaping_ratio as difference reward improves

3. **Convergence**: Stable balance between base reward and shaping

4. **CP Reduction**: Monotonic decrease in avg_cp_before over training

5. **Performance**: Improved sample efficiency compared to base difference reward

============================================================================================
TUNING GUIDELINES
============================================================================================

1. **cp_coefficient**: Start with 1.0, increase if shaping_ratio too low

2. **cp_discount**: Keep close to 1.0 (e.g., 0.99) for long-horizon guidance

3. **cp_normalize_mode**: Use "divide_by_p75" with cp_scale for varying graph sizes

4. **Monitoring**: Watch shaping_ratio - should be significant but not dominating

This report documents the implementation of advanced metrics for comprehensive monitoring
of the training process. These metrics provide insights into convergence behavior,
critical-path effectiveness, and potential issues during training.

============================================================================================
NEW METRICS IMPLEMENTED
============================================================================================

1. **lat_MA20** (Moving Average 20)
   - Rolling 20-iteration average of latency
   - Smooths out noise to show true convergence trend
   - Uses deque with maxlen=20 for efficient computation

2. **gap_MA20** (Gap Moving Average 20)
   - Rolling 20-iteration average of (latency - greedy_latency)
   - Shows how close the learned policy is to greedy baseline
   - Negative values indicate better-than-greedy performance

3. **CP_before_med** (Critical Path Before Median)
   - Median of all cp_before values in iteration
   - Excludes non-finite values
   - Indicates typical remaining work before decisions

4. **CP_after_med** (Critical Path After Median)
   - Median of all cp_after values in iteration
   - Should satisfy: CP_after_med ≤ CP_before_med + small_threshold
   - Validates CP reduction property

5. **CP_drop_med** (Critical Path Drop Median)
   - Median of (cp_before - cp_after) per step
   - Shows typical CP reduction per decision
   - Higher values indicate more effective scheduling

6. **shape_base_ratio_med** (Shaping/Base Ratio Median)
   - Median of |shaping_contribution| / (|base_step_score| + ε)
   - Indicates relative influence of shaping vs base reward
   - Values >> 1 suggest shaping domination (may need tuning)

7. **clamp_hit_frac** (Clamp Hit Fraction)
   - Fraction of steps hitting reward_clip_range bounds
   - High values suggest clipping is limiting learning
   - Should decrease as policy improves

8. **cp_violation_count** (CP Violation Count)
   - Count of steps where cp_after > cp_before + small_threshold
   - Should always be 0 (invariant validation)
   - Non-zero indicates algorithmic issues
