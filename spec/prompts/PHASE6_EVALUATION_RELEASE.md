## Baseline suite (all under the same `schedule()`, split, profiles, seeds)
Heuristics (deterministic, seedless): all-UE, all-MEC, all-HELPER, publication greedy (`greedy_plan`, from empty), greedy_from_mec (`greedy_from_mec_plan`), HEFT-style list scheduler over the three processors with the same communication model (implement in `scheduler/greedy.py` as `heft_plan`; document it as HEFT with our route table, cite Topcuoglu 2002), 2-opt (`iterate_2opt`; report as a search reference with its eval count, not as a learned competitor).
Learned baselines (5 seeds each, same encoder budget):
- PPO-from-scratch: Phase X configuration with the **corrected** outer update (see below), 500 iterations, adaptation 20 PPO steps on support, evaluate greedy decode on query.
- MRLCO-style: sequence encoder (no graph edges), binary Local/MEC (`vocab_size=2`, greedy `{0,1}` per `BINARY_ACTIONS`), latency-only, PPO inner K=3 on 20 trajectories, first-order outer; **with** the outer update implemented as averaged Reptile (`theta0` common origin, mean displacement, one update, task policies synchronized before the first rollout, fresh inner optimizer state per task — audit C-05/C-06/H-01) and PPO value clip centred on `v_old` (C-04). Document in `spec/decisions/ADR-014-baseline-fixes.md` with file:line for each fix and a unit test for order invariance (permute task order → identical update within 1e-6).
- GAT-Seq2Seq + PPO (FedMAGS-style, single server, no federation): uses the Phase 1 `gatv2` encoder with the PPO-from-scratch loop. This answers "is the gain from the encoder or from the training paradigm".
- BC zero-shot (v0.3 policy, k=1), BC best-of-k (k from ADR-008), BC + adaptation (Phase 3 rule, N_adapt from ADR-011), and, if Phase 4 kept it, BC + context.
Ablations (seed 0–4): encoder (meanagg/gatv2/dagformer), readout (triple/mean/max/attn/zero), teacher (greedy_from_mec vs 2-opt), adaptation loss (pg_il / pg / il / ce2opt), adapted subset (film/emb/lastlayer/full-θ), k ∈ {1, 8, 32}.

## Protocol
- Meta-test tasks: 5 distributions × 8 held-out profiles (Phase 4) = 40 tasks; support 20 / query 80. Zero-shot on query; adaptation on support only; report query at adaptation budgets {0, 5, 10, 20, 50, 100} (steps) **and** in evals-per-graph so PPO steps and EAS steps are comparable by compute, not by "steps".
- Metrics: T (s), E (J), J_λ for λ ∈ {1.0, 0.5, 0.0}, occupancy mix, `n_non` p50, evals per graph, inference latency per graph (ms of wall-clock on the RTX 4090 and on one CPU core — this is the one place "ms" is allowed, and it refers to inference time, not makespan), adaptation wall-clock, parameter count.
- Statistics: 5 training seeds × 40 tasks. Report mean ± std over seeds and 95% CI (t-distribution, n=5). Paired comparison per graph (same graph, method A vs B): Wilcoxon signed-rank on per-graph T; report p and effect size (median paired difference in seconds). Pre-register the primary comparison: **BC+adaptation vs greedy_from_mec on query T at λ=1.0** and **vs 2-opt J_0.5**. Everything else is secondary.
- Also report the old paper's greedy reference (publication greedy from empty) so the reader sees why previous "25% over greedy" claims are weak.
