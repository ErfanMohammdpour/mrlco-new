# MARGO-AUTOMOTIVE-MC-v1 — Dataset Contract (frozen before generation)

Status: contract locked; generation not started. This file fixes the rules that
`SOURCE_REGISTRY.yaml`, the generator, calibration and certification must obey.
Changing any rule here requires a dataset version bump.

## 1. What this dataset is

A **source-grounded synthetic automotive mixed-criticality DAG benchmark**:
application semantics, timing/SLA anchors and workloads are taken from, or
calibrated to, identified external sources; the graph population itself is
generated (controlled diversity), and feasibility is verified independently by
the scheduler. It is NOT a measured automotive dataset and must never be
described as one.

## 2. Provenance vocabulary (every generated field carries exactly one label)

| label | meaning |
|---|---|
| `measured` | value read directly from a measurement/trace in the cited source |
| `standard-derived` | value taken from an official standard/requirement clause |
| `trace-fitted` | distribution fitted to a cited trace/benchmark |
| `source-calibrated-synthetic` | generated, but calibrated so a derived quantity matches a cited range; the calibration rule is recorded |
| `synthetic` | generated by design with no external anchor |

A number without a `source_id` may only be `source-calibrated-synthetic` or
`synthetic`. Fabricating a source is forbidden; a missing anchor is recorded as
missing.

## 3. INVARIANT-TASK RULE (locked)

Compute workload and communication payload are **properties of the task and of the
edge**, never of the chosen action or link.

A task keeps ONE workload `W_i` regardless of whether it runs on UE, HELPER or
MEC, and an edge keeps ONE payload `B_e` regardless of which radio carries it:

```
W_i = t_ref_i * f_ref / (8 * xi)          # bytes, from a REFERENCE tier
T_i^UE     = 8 * xi * W_i / f_UE
T_i^HELPER = 8 * xi * W_i / f_HELPER
T_i^MEC    = 8 * xi * W_i / f_MEC
T_tx,e     = 8 * B_e / R_link             # only R varies, never B
```

Consequences that are enforced in code and tests:
- `compute_workload_bytes` is written once per task in the manifest and never
  recomputed from a placement;
- `task_output_bytes` / `external_input_bytes` are written once per edge/task and
  never resized per radio link;
- a calibration that "adjusts the payload to fit the link" is invalid: if the
  payload does not fit the SLA at the source-backed rate, the resource profile or
  the SLA interpretation is wrong, not the payload.

`f_ref`, `xi` and the reference tier are declared explicitly in
`workload_model.yaml`; the reference tier is a calibration device, not a claim
about where tasks run.

## 4. SLA scope (locked) — a communication requirement is not a DAG deadline

Every numeric row in `SOURCE_REGISTRY.yaml` and every SLA row in
`sla_registry.yaml` carries TWO independent fields. Scope alone is not enough:
two values can share a scope while meaning different things (for example a stage
deadline requirement versus a measured P95 latency of that stage).

`measurement_scope`:

| measurement_scope | meaning | may it define `D_G`? |
|---|---|---|
| `communication` | radio/interface latency or message transfer budget (e.g. a V2X service requirement) | no |
| `processing_stage` | one application stage or a chain segment (perception, planning, ...) | only via composition |
| `application_e2e` | end-to-end application/safety deadline for a use case | yes, this is the `D_G` anchor |

Rules:
- a `communication` value may constrain hop budgets or sub-deadlines, never the
  graph-level deadline directly;
- an `application_e2e` value must be traceable to a use-case requirement or a
  measured application chain, with the clause/table recorded;
- when a source gives a range, a deterministic pre-declared sampling/binning rule
  is used (recorded), and the chosen bin is stored per graph;
- the same numeric value with different scopes is stored as different entries.

`semantic_role` (independent of scope):

| semantic_role | meaning |
|---|---|
| `requirement` | a required bound/deadline stated by a standard, an application or a paper's contract |
| `measured_latency` | an observed latency (mean/P95/max) reported by a source |
| `execution_time` | observed execution/compute time of a task or stage |
| `payload` | a message/frame/dataset size |
| `offered_load` | a traffic/message-rate demand |
| `capacity` | an achievable rate/capacity of a resource |

Only `requirement` rows with `measurement_scope: application_e2e` may anchor
`D_G`. A `measured_latency` row is evidence, never a requirement, and may not be
declared an SLA.

## 5. Calibration order (hard gate)

```
external SLA fixed first
  -> workload/payload/resource distributions calibrated second
  -> graph deadline and subdeadlines frozen
  -> independent certification last
```

Current status: `timing_scale = UNRESOLVED`. The historical co-physical stack
produces 528–1245 s of makespan, and no source-backed application-level E2E target
has been frozen yet, so the mismatch cannot honestly be called an inconsistency
until such a target exists. What IS established is that the present
`communication`-scope values (3–50 ms message requirements) cannot be attached to
a perception+planning+control chain deadline. Workloads are derived from **measured/reference stage
times** (`t_ref_i`) at a declared reference tier, not invented as bytes and hoped
to be realistic.

Before `resource_profiles.yaml` is frozen, the currently frozen radio rates
(7 Mbps UL/DL, 5 Mbps V2V) must be re-evaluated against authoritative V2X
sources; if they disagree, the profile is changed and the change is recorded.

## 6. Four independent axes (never aliases of one another)

| axis | field | what it is |
|---|---|---|
| safety criticality | `criticality_class` | consequence of failure for the application |
| deadline urgency | `deadline_type` + `deadline_s` | how strict the timing requirement is |
| tardiness weight | `tardiness_weight` | cost shape used by the objective/metrics |
| execution-demand uncertainty | `execution_budget_lo/hi` | LO/HI demand model (mixed criticality) |

`criticality_class` MUST NOT be derived from node depth, topological index,
decoder order, workload magnitude or edge count. Those may be logged as
diagnostics only, and `CRITICALITY_AUDIT.md` must show that class is not an
effective deterministic function of depth (table + association measure).

## 7. Mixed-criticality execution semantics

HIGH tasks carry `C_LO` and `C_HI` with `C_HI >= C_LO > 0`, derived from
measured/fitted demand distributions; they are named `empirical_execution_budget_*`
unless the source genuinely provides WCET. LOW/MEDIUM must state whether `C_HI`
exists or is `not_applicable`. Operating modes are `LO/nominal` and
`HI/overload`, entered only on an explicit recorded trigger (HIGH demand above
`C_LO`, an overrun event, or a resource-degradation event). Every episode stores
the mode-switch reason. HIGH tasks are never silently dropped; LOW tasks may be
deferred only where `drop_allowed_hi_mode` is true.

## 8. Deadline construction (non-circular, locked)

```
D_G  <- external application_e2e anchor (frozen before any scheduling)
E_i  <- forward earliest achievable bounds
L_i  <- backward latest admissible times from D_G
S_i  = L_i - E_i >= 0        E_i <= d_i <= L_i
```

Forbidden: `D_G = kappa * T_witness`; scheduling a graph and choosing its deadline
from the observed completion; replaying the witness schedule as the feasibility
proof of a deadline derived from it. Criticality may shape the slack
distribution, never the external SLA. Tests must prove the witness/search routine
is not called before `D_G` is fixed.

## 9. Independent certification (after freeze)

Certification runs only after topology, workloads, payloads, resource profile,
SLA, subdeadlines, criticality and `C_LO/C_HI` are frozen, and it may not modify
any of them. It records `certified_feasible` / `witness_not_found` / `stress` with
the method, search budget, placement, makespan, misses, slack and system energy.
`witness_not_found` is never reported as mathematical infeasibility, and an
uncertified graph is never silently treated as impossible.

## 10. Splits at the generating-factor level

Splits are built from latent factors (application family, motif lineage, parent
RNG seed, topology regime, workload regime, resource profile, SLA/tightness
regime, criticality mixture), not by shuffling files. Graph duplicates, forbidden
topology duplicates, parent-seed families and support/query pairs must not cross
roles; the leakage checker exits non-zero on any violation. Calibration may use
the meta-train calibration subset only. meta-test stays unopened until the freeze.

## 11. Acceptance

The dataset is accepted only if all 20 checks in the generation window pass,
including: deadlines not witness-derived and not arbitrary; criticality not
depth-derived; physically coherent time scale under the co-physical scheduler;
neither trivial nor impossible population; no single pure placement dominating;
no leakage; complete provenance; deterministic regeneration from
`generator + config + source registry + seed`. Any failure => DATASET BLOCKED.

## 12. Legacy preservation

`meta_offloading_20` and `meta_offloading_n` stay untouched for reproduction. The
historical mixed-physics regime (`deadline_regime.py` with its witness anchoring)
remains available for the legacy dataset only and is not the source of any
`MARGO-AUTOMOTIVE-MC-v1` deadline.
