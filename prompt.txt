2) Define “incremental makespan” precisely
At any decision step (choosing local vs remote for the current task):
•	The current schedule state includes:
o	makespan_now: max finish time of already placed tasks.
o	Resource clocks: next-free times for UE CPU, MEC CPU, and Uplink channel.
o	Finish times of all predecessors already scheduled.
•	For Local candidate:
1.	Earliest start = max(UE_CPU_free, max(finish_times_of_predecessors)).
2.	Finish_local = start + local_exec_time(task).
3.	Candidate_makespan_local = max(makespan_now, Finish_local).
4.	Δ_loc = Candidate_makespan_local − makespan_now.
•	For Remote candidate:
1.	UL_start = max(UL_free, max(finish_times_of_predecessors)).
2.	UL_finish = UL_start + uplink_time(task).
3.	MEC_start = max(MEC_CPU_free, UL_finish).
4.	MEC_finish = MEC_start + mec_exec_time(task).
5.	DL_finish = MEC_finish + downlink_time(task) (this is the task’s finish time).
6.	Candidate_makespan_remote = max(makespan_now, DL_finish).
7.	Δ_rem = Candidate_makespan_remote − makespan_now.
Important details:
•	Use the same time units (e.g., milliseconds) throughout.
•	Treat “no change” as Δ = 0 (happens when the task completes before the current makespan).
•	Use a small epsilon (e.g., 1e-9) for equality checks to avoid float noise.
3) Add a dry-run evaluator (no mutations)
•	Before committing an action, compute Δ_loc and Δ_rem using a pure, non-mutating preview of the schedule (you simulate the timestamps but do not update any live resource clocks or finish times).

•	Sanity check:
o	If you preview an action and then actually take it, the incremental makespan you observe for real must match the previewed Δ for that action (up to epsilon).
4) Compute the difference reward at each step
For the action sampled by the policy:
•	Δ_chosen = Δ_loc or Δ_rem corresponding to the sampled action.
•	Δ_best = min(Δ_loc, Δ_rem)
•	Δ_worst = max(Δ_loc, Δ_rem)
•	Unnormalized base reward:
r_main = Δ_best − Δ_chosen
(This is positive if you picked the better of the two; negative if you picked the worse; zero if they’re equal.)
5) Normalize per step (to fix scale)
•	If Δ_worst > Δ_best (strictly, beyond epsilon):
r_norm = r_main / (Δ_worst − Δ_best)
else set r_norm = 0 (both choices equally good/bad).
•	Clip r_norm to [−1, +1].
•	This r_norm is your entire reward for Step 1 (no other terms yet).

•	Both Δ = 0 → r_norm = 0 (choice doesn’t affect makespan).
•	Numerical ties (|Δ_loc − Δ_rem| < epsilon) → treat as equal → r_norm = 0.
•	Huge Δ_worst − Δ_best → clipping protects your advantages from exploding.
